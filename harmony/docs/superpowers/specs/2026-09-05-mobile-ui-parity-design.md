# Huoqu 鸿蒙端手机 UI 1:1 复刻设计

## 目标

将当前鸿蒙客户端的 UI、操作方式和交互反馈与 `xyz9810010/huoqu` 仓库当前版本（基准提交 `acee27a`）的手机端网页保持一致，同时继续使用现有 ArkTS API、会话、通知、扫码、拨号和导航能力。

本项目中的“1:1”指在同等手机视口、相同角色、相同数据和相同页面状态下，页面的信息层级、布局、尺寸、间距、颜色、圆角、边框、字体层级、图标语义、导航路径、控件状态、点击结果、加载反馈、空状态、错误反馈和弹窗流程与参考网页一致。系统状态栏、系统键盘、系统权限框以及鸿蒙原生控件不可消除的平台渲染差异不计为偏差。

## 范围

覆盖所有角色及其可访问页面：

- 老板/管理员：首页看板、客户、客户详情、任务、任务详情、区域、员工、日志、通知、通知设置、消息推送配置，以及角色权限允许的其他页面。
- 客服：客户、客户详情、新建取件、任务、任务详情、待匹配中心、通知和通知设置。
- 取件员：我的任务、任务详情、我的数据、通知和通知设置。
- 公共流程：登录、退出登录、角色首页跳转、顶部导航、抽屉菜单、通知入口、返回行为、加载/空数据/请求失败状态。

不改变后端接口语义、鉴权规则、业务数据模型或参考项目之外的功能。

## 参考基准

视觉与交互的唯一基准为参考仓库 `web/src`：

- 全局视觉变量和手机端通用规则：`web/src/styles/theme.css`
- 导航与角色菜单：`web/src/views/Layout.vue`、`web/src/router.ts`
- 页面布局和交互：`web/src/views/*.vue`
- 基准宽度：优先使用 360、390、430 vp 三种手机内容宽度比对。

## 实现方式

采用纯原生 ArkUI 复刻。现有页面保留业务职责和 API 调用，视觉结构迁移到统一设计系统组件；不使用 WebView，也不复制 Vue 运行时。

新增公共 UI 层，预计包含：

- `Theme.ets`：颜色、字号、间距、圆角、边框和阴影常量。
- `AppShell.ets`：56 vp 手机顶部栏、通知入口、用户头像和 264 vp 左侧抽屉。
- `PageComponents.ets`：页面标题、工具栏、卡片、状态标签、手机字段行、操作按钮组、加载和空状态。
- `Icons.ets` 或媒体资源：使用与 Element Plus 图标语义一致的矢量资源，避免用 emoji 代替正式图标。

公共组件只封装表现和通用交互，不持有页面业务数据。各页面继续负责数据获取、表单状态、权限判断和 API 调用。

## 操作与交互规范

### 导航

- 登录后按参考规则跳转：老板/管理员到看板，客服到任务，取件员到我的任务。
- 手机端始终使用 56 vp 顶栏；左侧圆形菜单按钮打开 264 vp 抽屉。
- 抽屉只显示当前角色可访问菜单，当前项使用浅蓝背景、品牌蓝文字和图标。
- 点击抽屉遮罩或菜单项关闭抽屉；系统返回键优先关闭抽屉/弹窗，再返回上一页。
- 顶栏通知按钮显示未读角标；头像菜单提供退出登录。

### 表单

- 字段顺序、默认值、必填标识、禁用条件、占位文本和提交校验与 Vue 页面一致。
- 手机端输入和选择控件占满可用宽度，主要点击目标不小于 44 vp。
- 提交期间显示加载并阻止重复提交；成功后执行与网页相同的清空、关闭、刷新或跳转。
- 密码字段支持显示/隐藏，敏感配置按参考页面遮罩。

### 列表与详情

- 小于等于 768 vp 的参考网页手机列表结构作为鸿蒙唯一手机布局，不照搬桌面表格。
- 卡片字段、字段标签宽度、对齐、换行、截断和操作按钮排列与网页一致。
- 可点击卡片、按钮和文字入口保持同样的点击区域与导航结果。
- 状态颜色、优先级颜色、任务类型标签和异常提示由统一映射提供。

### 反馈状态

- 首次加载显示居中加载状态；无数据显示对应页面的空状态；刷新时保留符合参考页面的现有内容行为。
- 请求失败使用可见提示，文本优先采用服务端消息，并恢复按钮可操作状态。
- 删除、取消、完成、匹配等不可逆或关键操作使用与网页等价的确认弹窗。
- 通知、表单保存、扫码和权限失败均提供明确反馈，不静默失败。

### 原生能力

- 网页中的拨号、地图导航、扫码、图片选择和系统通知在鸿蒙端调用现有原生实现。
- 原生权限请求只在首次需要时触发；拒绝后给出可恢复说明。
- 平台能力的最终结果必须与网页操作目标一致，即使系统弹窗外观不同。

## 数据流与权限

- `SessionStore` 继续保存令牌、用户、角色和服务地址。
- 页面通过现有 `*Api.ets` 服务访问统一后端，公共 UI 组件不直接发请求。
- 菜单、路由入口和页面进入时均按参考角色权限限制；无权限访问返回角色首页。
- 通知未读数、实时事件和页面刷新沿用现有服务层，并在公共顶栏显示。
- 页面退出或切换时清理页面级监听，避免重复事件和重复请求。

## 中文与资源

- 所有 ArkTS 和资源文件统一为 UTF-8，修复现有乱码字符串。
- 公共文本优先放入资源文件；动态业务文本在 ArkTS 中保持 UTF-8。
- 图标优先采用本地矢量资源，并与参考 Element Plus 图标在含义、大小和颜色上匹配。
- 不依赖网络图标、emoji 或设备字体中的偶然字形。

## 验证与验收

### 构建验证

- 使用项目自带 Hvigor 或 DevEco Studio 完成 debug 构建。
- ArkTS 类型检查无错误，页面资源引用无缺失。

### 功能验证

- 使用老板/管理员、客服、取件员账号逐一验证可见菜单、默认首页和全部允许路由。
- 对每个页面验证正常数据、空数据、加载、请求失败以及关键弹窗状态。
- 验证登录/退出、返回、抽屉、通知、搜索、筛选、表单、任务操作、拨号、导航、扫码和设置保存。

### 视觉验证

- 同一数据下分别截取参考网页和鸿蒙页面的 360、390、430 宽度截图。
- 按页面做并排或半透明叠图比较，检查结构、边距、字号、颜色、圆角、图标、卡片高度和换行。
- 视觉偏差目标：主要布局位置不超过 2 vp，颜色使用相同设计变量，文字层级与控件状态无肉眼可辨差异。
- 对系统状态栏、系统键盘、权限弹窗等平台所有的区域单独标注，不纳入页面像素偏差。

## 实施顺序

1. 建立主题、图标和公共壳层，修复中文编码。
2. 完成登录与角色导航，建立全局交互基准。
3. 完成任务主链路：客服任务、派单、任务详情、取件员任务。
4. 完成看板、客户和匹配中心。
5. 完成区域、员工、日志、个人数据。
6. 完成通知、通知设置和推送渠道配置。
7. 全角色回归、三档手机宽度视觉比对和最终修正。

## 完成定义

- 参考网页的全部手机端角色页面均有对应鸿蒙实现。
- 页面结构、视觉和交互符合上述 1:1 标准。
- 不存在乱码、emoji 占位图标、明显缺页或角色越权入口。
- 工程可以通过 debug 构建，并完成全角色核心流程验证。
- 已记录无法消除的平台级差异，除此之外没有已知的视觉或交互偏差。
